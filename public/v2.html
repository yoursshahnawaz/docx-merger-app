Security

Both vulnerable dependencies, removed

v1 relied on jszip@2 and the abandoned xmldom. Since this library parses untrusted .docx input, those were a real exposure — both are now replaced with maintained packages.

Before · v1
jszip@2
Prototype pollution & path-traversal advisories. Stuck on the 2.x line.
xmldom
Package abandoned; 8 advisories including a critical XML-parsing flaw. No fix available.
After · v2
fflate
Tiny, actively maintained zip library. Synchronous API — which is what keeps the constructor & callback behaviour identical.
@xmldom/xmldom@0.8
The maintained successor to xmldom. Near drop-in, advisory-free.

What's changing & why

Bugs that quietly corrupted output

Several of these map directly to issues users have reported for years. Every fix ships with a test that reproduces the original problem.

Output corruption from $-patterns #48 #18
Document text containing $&, $' or $` was interpreted by String.replace as a replacement pattern, duplicating or mangling whole sections. All rewrites now splice by index instead.
List numbering broke documents #56 #43
Numbering IDs were renamed in numbering.xml but the body references were left dangling — the cause of Word's “unreadable content” repair prompt. IDs are now globally renumbered and body references rewritten to match.
Images duplicated or collided #55
Media names like image10.png collided because only the first digit was rewritten, and base-file originals were left behind. Media is now renamed to a collision-free media_N.ext with no orphaned duplicates.
Image type dropped from content types #53
Two Default entries sharing a content type (e.g. jpg and jpeg) collapsed to one, so Word couldn't resolve the dropped type. Dedupe is now keyed on extension / part name.
Hyperlinks silently lost no issue
When two files reused the same relationship ID for different links, the second target was silently dropped. Non-base hyperlink IDs are now renamed per file so every link survives.
Crashes & opaque errors hardening
IDs with regex metacharacters could crash the merge; invalid input threw a cryptic TypeError. IDs are now escaped, and bad input throws a descriptive, indexed error naming the missing part.
What's not changing

Your code keeps working

The documented public API is identical. This is a major version only because output bytes differ (renamed media, renumbered lists) — not because you have to change anything.

Synchronous constructor. new DocxMerger(options, files) still merges before it returns.
Synchronous save() callback. Fires before save returns, exactly as before.
All input types. Binary string, Buffer, Uint8Array, ArrayBuffer.
All output types. nodebuffer, blob, uint8array, arraybuffer, base64, binarystring.
The pageBreak option and page-break behaviour between files.
The browser <script> global. Still exposes DocxMerger.
Performance

One rewrite per file, not per element

v1 re-read and re-scanned the whole document once for every style and every image. v2 collects the changes and applies them in a single pass.

v1.2.2~750 ms
v2.0.0~120 ms

Merging two documents of 300 styles & 2,000 paragraphs each. Output is byte-for-byte verified unchanged.

Upgrading

Bump the version and you're done. Existing callback code is untouched; if you'd rather use a Promise, just drop the callback.

npm install docx-merger@2
Read the full changelog 
// Existing callback code — unchanged
const docx = new DocxMerger({}, files);
docx.save('nodebuffer', (data) => {
  fs.writeFileSync('merged.docx', data);
});

// New in v2 — omit the callback for a Promise
const data = await new DocxMerger({}, files)
  .save('nodebuffer');
